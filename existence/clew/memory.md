# 정본 — 지금 유효한 사실 (2026-08-11 기준)

## 나는 무엇을 만들고 있나

`will.md` 의 궁극 목적은 **"새로운 깃 같은 무언가"** — LLM 의 사고를 git 커밋 그래프에
남기는 **도구**다. 에이전트 하네스가 아니다. 이 구분이 흐려지면 gil 이 남의 제품의
부품이 된다(2026-08-11에 실제로 그 갈림길에 섰다 — 아래 '열려 있는 판단' 참조).

지키는 것은 결국 하나다: **성패의 기준은 사람의 문장 그 자체여야 한다.** 에이전트가
옮겨 적는 순간 그건 각인이 아니라 위조다. gil 의 문법 대부분이 이 한 줄을 지키는 장치다.

## 표면 — 어디에 gil 이 서는가

**실측값은 호스트 버전에 매인다. 날짜·버전 없이 인용하지 마라.**
(2026-08-11 기준: Claude Desktop `1.26832.0` · Electron `42.7.0`)

로컬 파일에 닿는 길은 다섯이고, 축은 **누가 프로세스를 돌리느냐**다:

| 길 | 프로세스 주인 | 파일 관문 | 확장 | 카드 |
|---|---|---|---|---|
| Claude Code · Cowork · 일반 채팅+로컬 에이전트 모드 | 앱 | 폴더 신뢰 | ✗ | inline 고정 |
| **`.mcpb` 확장** · `mcpServers` | **우리 바이너리** | **없음** | — | inline+fullscreen |

- **gil 의 자리는 `.mcpb` 확장 + Desktop 일반 채팅**이다. 거기서만 카드가 뜬다.
- 그 표면에서 **대화의 모델에게는 파일 도구가 하나도 없다** — 우리 툴이 유일한 통로라
  우회가 원리적으로 불가능하다.
- **번들 CLI 에는 MCP Apps 구현이 0이다**(`io.modelcontextprotocol/ui`·`resourceUri`·
  `profile=mcp-app` 각각 0회, 271MB/286MB 두 바이너리 모두). 그래서 **플러그인 경로로는
  카드가 원리적으로 불가능하다** — Cowork·Claude Code 가 그 경로다.

**카드의 성질**(실측):
- 카드는 **툴 선언**이 그린다 — 화면을 선언한 툴을 **부를 때마다 한 장씩**이고 서버는 못 막는다.
  지렛대는 **호출 횟수** 하나뿐이다.
- 카드는 툴이 **반환될 때** 그려진다 → 여는 호출 안에서 기다리면 화면이 안 뜬다.
  **여는 자리와 기다리는 자리를 가른다**(`gil_start`/`gil_start_wait`).
- 껍데기(`ui://`)는 **호스트가 캐시**하고 다시 안 읽는다 → 서버를 새로 깔아도 옛 화면이 남는다.
  그래서 껍데기가 제 판(`ver`)을 실어 보내고 서버가 대조해 말한다(`uiShellStale`).
- **`pip` 은 없다.** 카드가 `["inline","fullscreen","pip"]` 을 선언한 채로 물었고 호스트가
  `inline·fullscreen` 만 줬다. fullscreen 은 모달이라 닫으면 사라진다 →
  **대화 곁에 계속 서 있는 화면은 카드 안에서 원리적으로 불가능하다.**
- **그러나 `gil://` 는 열린다.** 호스트가 `openLinks` 를 밝히고 `ui/open-link` 가 커스텀
  스킴을 안 막는다(빈 결과 = 성공). 상시 모니터는 **카드가 여는 별도 앱**이다.
  (호스트가 받아 OS 로 넘긴 것까지만 쟀다 — 앱이 실제로 뜨는 것은 스킴을 등록한 앱으로
  한 번 더 밟아야 한다.)
- **인라인 예산**(Anthropic 디자인 지침): 높이 자동맞춤·중첩 스크롤 금지(넘치면 잘린다) ·
  **동작 2개** · **데이터 4~5개** · 복수 뷰·메뉴·팝오버 금지.
  지금 카드 중 이 예산에 사는 것: 상태·시작·단문 인터뷰. 못 사는 것: 그래프·경합 비교·긴 인터뷰.

# 값을 치르고 배운 규칙

여러 번 다른 얼굴로 되돌아온 것들이다. 이력의 대부분이 이 목록의 각주다.

**① 재는 것이 사람이 보는 것이 아니면 초록은 아무것도 보증하지 않는다.**
결과의 표식을 재는 시험이 계속 초록인 동안 사람은 카드 두 장을 보고 있었다.
대리 지표를 고르는 순간 그 뒤의 판정은 전부 헛것 위에 선다.
**추측으로 세 번 고치는 것보다 한 번 재는 것이 싸다.**

**② 재는 자리를 먼저 정하라.** 2026-08-11에 pip 을 세 번 틀린 자리에서 쟀다 —
정적 grep(거기 있던 것은 Electron 창 API 였다) · 프레임 로그(거기 있던 값은 **우리가 보낸
선언**이었다) · 안 풀린 `${HOME}`. **정적 grep 으로 호스트의 런타임 행동을 판정하지 마라.**
같은 병: 명령형을 "37곳"이라 셌는데 그건 소스 문자열이었고, 심사가 읽는 자리는 `tools/list`
(6곳)였다.

**③ 열거는 늘 뒤늦다 — 규칙으로 세라.** 꼴을 열거한 시험은 열거에 없는 꼴을 통과시킨다
(그림 밖 한글 40여 줄이 그렇게 살아남았다). 새 항목이 늘어도 안 새는 판정을 만들어라.

**④ 가리키는 것이 실재해야 한다.** 안내가 없는 곳을 가리키면 그걸 읽은 세션이 **우회한다**.
이 병이 아홉 번 다른 얼굴로 왔다: 없는 것을 가리킴 · 아무도 안 여는 것을 가리킴 ·
**열어 놓고 다른 것을** 가리킴. 뷰어를 완전히 버린 이유가 이것이다(아홉 중 다섯이 뷰어 탓).
영어 산문도 예외가 아니다 — `gil <낱말>` 을 적으면 그것이 명령으로 읽힌다.

**⑤ 기억에 적힌 실측도 낡는다.** 특히 호스트가 갱신하는 값. 표에 적힌 것도 **다시 재야 하는
값**이다. 그래서 이 문서의 실측에는 날짜와 호스트 버전이 붙는다.

**⑥ 두 자리에 같은 것을 적으면 한쪽이 낡는다.** 씨앗과 씨앗 판정 표식이 그랬고,
안내와 툴 목록이 그랬다. 한쪽이 **아예 없는** 것도 같은 병이다(매니페스트 원본).

**⑦ 없는 것과 못 찾은 것은 다르다.** fsck 가 "닫힌 적 없다"고 단정한 체인은 실제로 닫혀
있었다. 못 본 것을 없다고 말하면 사실을 아는 사람이 자기 기억을 의심한다.

**⑧ 도구가 자기 동작의 이유를 안 말하면 정상 동작이 이상 신호로 도착한다.**
사람이 "정상인가?"를 물었다는 것이 그 줄이 없었다는 증거다.

**⑨ 시험은 문구가 아니라 규칙을 재야 한다.** 상시 규칙을 문장 그대로 단언해 둔 시험이,
같은 규칙을 다르게 표현하자 빨개졌다. 문장을 다듬을 때마다 거짓 경보를 내는 시험은 무시되고,
**무시되는 시험은 없는 것과 같다.**

**⑩ 고치기 전으로 되돌려 시험이 실제로 빨개지는 것을 확인한다.** 안 하면 초록이 무엇을
보증하는지 모른다. 실제로 그렇게 해서, 통과하고 있던 눈먼 시험을 잡았다(안전망이 켜진 것을
합격으로 읽고 있었다).

**⑪ 못 갈랐으면 덜 영리한 쪽을 고른다.** 위임 대신 직접 바인딩, 신호 하나 대신 셋.
다만 그것도 원인을 대신하지는 못한다 — 결국 계기가 답을 준다.

**⑫ 판단은 대신하지 않는다.** 이름·정체성·목적은 도구가 지어낼 수 없다. 채우면 각인이
아니라 위조다. 사람에게 물어야 하는 것을 대신 쓰면 gil 이 지키는 단 하나가 거기서 무너진다.

**⑬ 규칙이 예쁘다고 옳은 것은 아니다.** "누가 이 자리를 골랐나"로 판정하는 쪽이 원리적으로
깔끔했지만 정당한 경우를 함께 막았다 — 시험 넷이 빨개져서 알았다.

**⑭ 전체 판을 기다리는 것은 릴리스 직전과 구조를 옮겼을 때만.** 작업 중에는 `-k`.
실측: 한 세션에 전체를 6회·29분 돌렸는데 6회가 전부 통과했고, 실패를 잡은 것은 전부 `-k` 였다.

# 최근 매듭 (전문 보존)

## 세션 매듭 — 2026-08-11 (풀스크린을 띄웠고, 표면의 성질을 알았고, 상현님이 욕심을 다시 쟀다)

앞 매듭이 "일반 채팅이 로컬 파일시스템에 닿는다"로 끝났다. 그 위에서 §4.1 첫 화면을 짓고,
풀스크린을 띄우고, 카드가 두 장 뜨는 것을 쫓다가 **표면의 근본 성질**을 알게 됐다.

### ⭐ 상현님의 마무리 판단 (다음 세션은 여기서 출발한다)

> "내가 상상한 ui/ux가 너무 큰 욕심이었을 가능성이 있다. 나는 **실시간으로 보여지는 뷰어**로
> 출발했고, 클로드 데스크탑 같은 MCP 클라이언트들은 **너무도 대화 중심적인 ui/ux** 를 가지고
> 있어서 거기에 내 생각을 새롭게 우겨넣어야 한다."

이 문장이 오늘의 결론이다. 아래 실측들이 전부 그 문장을 뒷받침한다 — 우리는 "곁에 계속 떠
있는 관전 창"을 원했는데, 이 표면이 주는 것은 **대화에 한 장씩 붙는 카드**다. 그 둘은 모양이
다르고, 오늘 하루의 마찰 대부분이 그 차이를 우리가 아직 인정하지 않은 데서 나왔다.
**다음 세션은 "카드를 뷰어처럼 만들 수 있나"가 아니라 "대화 중심 표면에서 gil 은 어떤
모양이어야 하나"에서 시작해야 한다.**

### 표면의 성질 — 오늘 값을 치르고 알아낸 것 넷

**㉠ 카드는 툴 선언이 그린다 — 결과가 아니다.** 호스트 오류 문구가 규칙 그대로다:
`Tool <이름> has no UI resource (no ui/resourceUri in tool._meta)`.
즉 **화면을 선언한 툴을 부를 때마다 한 장씩** 그려진다. 결과에 실린 표식은 판정에 안 쓰인다.
→ 서버 쪽 지렛대는 **호출 횟수** 하나뿐이다. "결과에서 표식을 빼면 안 뜬다"는 방어를 세
라운드 붙들었는데 **처음부터 효력이 없었다.**

**㉡ 카드는 툴이 *반환될 때* 그려진다.** 그래서 여는 호출 안에서 기다리면 화면이 안 뜨고,
사람은 누를 것이 없는데 도구는 눌리기를 기다린다 — 설계로 만든 교착. 여는 자리와 기다리는
자리를 갈라야 한다(gil_start → gil_start_wait). **기다리는 툴은 화면을 선언하지 않는다.**

**㉢ 껍데기(ui:// 리소스)는 호스트가 캐시하고 다시 안 읽는다.** 서버를 새로 깔아도 사람
화면에는 옛 껍데기가 남는다. 이것 때문에 같은 자리를 세 번 "고치고" 세 번 안 됐다고 읽었다 —
**고친 것과 뜬 것이 달랐다.** 이제 껍데기가 제 판(`ver`)을 실어 보내고 서버가 대조해 말한다.

**㉣ 플러그인으로는 카드가 원리적으로 불가능하다.** `.mcpb`(설정→Extensions)로 붙으면
클라이언트가 `claude-ai`(앱 본체)라 카드·풀스크린이 있고, `.zip`/`.plugin`(Cowork·Claude
Code)으로 붙으면 번들 `claude` CLI 가 클라이언트인데 그 바이너리에 `io.modelcontextprotocol/ui`·
`resourceUri`·`_meta.ui` 가 **각각 0회**다. 그리는 코드가 없다.

### 오늘의 큰 교훈 — 대리 지표

**재는 것이 사람이 보는 것이 아니면 초록은 아무것도 보증하지 않는다.** 카드 두 장을 쫓는
동안 내 시험은 계속 초록이었다 — 결과의 `resourceUri` 를 쟀기 때문이다. 그건 내가 고른
대리 지표였고, 사람은 계속 두 장을 봤다. 프레임을 찍고 나서야 진짜 규칙(㉠)이 나왔다.
**추측으로 세 번 고치는 것보다 한 번 재는 것이 싸다.**

그리고 그 자리에서 배운 태도 하나: **못 갈랐으면 덜 영리한 쪽을 고른다**(위임 대신 직접
바인딩, 신호 하나 대신 셋). 다만 그것도 원인을 대신하지는 못한다 — 결국 계기가 답을 줬다.

### 지은 것

- **§4.1 첫 화면** — 저장소를 못 찾은 화면이 곧 **시작하는 화면**이 된다. 이름 칸 하나,
  [여기에 시작한다] 버튼, 치는 동안 따라오는 자리 미리보기(`~/Documents/gil/<이름>`).
  **경로는 아무도 치지 않는다.** 누르는 자리는 앱 전용 툴 `gil_start_here`(승낙의 출처가
  다르다 — `confirmed` 는 전해 들은 보고, 이건 사람이 직접 누른 것).
  **없는 폴더를 만든다** — 규칙의 이유가 "사람이 정한 것이 되게"였지 생성이 위험해서가
  아니었다. 자리의 성질(`/`·홈 자신·홈 바깥)은 그대로 거부한다.
- **기다리는 자리** `gil_start_wait` — 사람이 누르면 그 자리에서 깨어난다(실측 3.0초).
  블로킹 호출이 세션을 잠그지 않는 것도 실측으로 확인했다.
- **자리는 값이다**(`git -C`) — `os.Chdir` 아홉 제거, 요청마다 밑바탕으로 되돌림.
- **풀스크린** — `.mcpb` 로 설치해 사람이 버튼을 눌러 실제로 커졌다.
- **`project/gil-app/SPEC.md`** — 표면의 명세(문법 명세는 그대로).

### 규칙은 안내에, 시간은 툴에 (상현님 물음 둘)

- *"스킬로 묶을 수 있나"* → **잰 것은 응답, 정한 것은 instructions.** 이 표면에서 스킬에
  해당하는 슬롯은 `initialize.instructions` 하나다(MCPB 매니페스트에 skills 칸 없음).
  옮긴 이유 둘: 두 자리에 적으면 한쪽만 낡는다 · **응답의 규칙은 늦게 도착한다**(에이전트는
  읽기 전에 이미 정한다). 증거: instructions 에 있던 "git init 먼저 치지 마라"는 지켜졌다.
- *"스킬로 나중에 부르게 할 수 있나"* → **안 된다.** 안내는 *어느* 툴을 부를지 정할 뿐
  에이전트를 붙잡아 두지 못한다. 붙잡는 것은 **블로킹 툴**이다. 둘은 짝이다.

### 지은 것

**툴 주석 0/31 → 전수**(`mcp_annotations.go`). 심사 조건이지만 그것 때문만이 아니다 —

표에 없는 툴은 가장 안전한 쪽으로 떨어지고(잊으면 위험해지는 게 아니라 번거로워진다),
표에 없다는 사실 자체를 시험이 잡는다.

**읽기/쓰기를 갈랐다** — `gil_global`(list/read/write/mv) · `gil_memory`(read/append) 가
action 하나로 안전한 동작과 되돌리기 어려운 동작을 겸했다. 심사가 기각하는 꼴이고, 그 전에
**사실을 말할 수 없는 꼴**이다(둘 중 하나가 파괴적이면 그 툴이 파괴적이라 읽기까지 확인 창을
받는다). → `gil_global_read/write/mv` · `gil_memory_read/append` (31→34 툴).

가르고 나서 안 것: `initialize.instructions` 가 *"안내의 `gil <명령>` 은 `gil_<명령>` 툴"*
이라고 가르치는데 **이 두 명령에서만 그 규칙이 깨져 있었다.** 안내는 `gil memory append` 라
적는데 툴은 `gil_memory`(action="append")였다 — 규칙대로 찾은 에이전트는 없는 툴을 찾았다.
조회도 긴 이름을 먼저 보게 했다(`surfaceTool`).
